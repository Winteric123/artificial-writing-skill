# Maintenance and reproducibility

This repository separates the distributed skill from repository-level documentation and automation. The distributable skill lives under `skills/artificial-writing-skill`; installed copies belong in the user's canonical skills root. The workflow and helpers in `.github` do not add literature records or change writing behavior.

## Automated checks

The [Repository checks workflow](.github/workflows/repository-checks.yml) runs on pushes to `main`, pull requests targeting `main`, and manual dispatch. Its matrix covers Ubuntu and Windows with Python 3.10 and 3.12. Consult the [actual workflow runs](https://github.com/Winteric123/artificial-writing-skill/actions/workflows/repository-checks.yml) for results for a particular commit; matrix configuration alone is not a passing result.

The workflow runs:

1. Tests of the repository-level checker.
2. Checks for prohibited tracked artifacts, root-document links, and executable README retrieval examples.
3. Read-only skill health checks of registers, provenance dependencies, and internal links.
4. The existing skill regression suite.
5. A check that tracked files were not modified.

The checks use the Python standard library and public tracked resources. They do not require source PDFs, API credentials, private manuscripts, or a model API. They do not rebuild catalogs or PDF locators. Official checkout and Python-setup actions are pinned to commit SHAs; the workflow token has read-only repository-content permission and is not persisted by checkout.

## Local verification

Run from the repository root with Python 3.10 or later:

```text
python -X utf8 -B -S -m unittest discover -s .github/tests -p "test_*.py" -v
python -X utf8 -B -S .github/scripts/check_repository.py
python -X utf8 -B -S skills/artificial-writing-skill/scripts/check_skill_health.py
python -X utf8 -B -S -m unittest discover -s skills/artificial-writing-skill/tests -p "test_*.py" -v
git diff --exit-code
```

Do not bypass an outdated dependency hash by editing the recorded hash alone. Follow the [skill maintenance sequence](skills/artificial-writing-skill/references/retrieval-and-maintenance.md) and inspect the source change before rebuilding. Preserve `.gitattributes`: the skill's content-addressed dependencies require unchanged file bytes across operating systems.

Reading completion and scientific acceptance are established by their documented source-review procedures, not by these checks. Writing-case evaluation remains a separate, recorded prompt/response assessment; CI does not perform a new one.

## Dated snapshots

Use a `snapshot-YYYY-MM-DD` tag, with a numeric suffix if a distinct same-day snapshot is needed. Publish only after the intended commit is pushed and its full workflow has succeeded. Record that exact commit in the release notes and link its workflow run and [changelog](CHANGELOG.md).

Initial dated snapshots are marked as prereleases. They identify a retrievable repository state, not a guarantee of API stability, clinical validity, exhaustive literature coverage, or independent scientific acceptance. Do not move an existing snapshot tag to a different commit; publish a new identifier for a changed snapshot.

Do not attach source PDFs, extracted full text, private study data, credentials, or local audit outputs to a release. The source archive generated by GitHub contains only the committed repository. A release does not select a license or confer rights to the underlying publications.

For research attribution, use the [citation and version-recording guidance](CITATION.md). Author metadata and an open-source license require an explicit maintainer decision; neither should be inferred from a Git username or a passing test.
